## 💡 The Problem

Peer-to-peer deals — a stranger buying your bike, a freelancer gig, a marketplace sale — run entirely on blind trust. There's no negotiation support, no neutral terms, and no safety net if one side doesn't hold up their end. Existing escrow is clunky, manual, and rarely built for everyday transactions.

<br>

<!-- ═══════════════ THE IDEA ═══════════════ -->

## ✨ The Idea

**Brokerage AI** is a peer-to-peer marketplace prototype with a structured, application-managed transaction flow. AI negotiation remains planned work.

> 🤖 Buyers and sellers can discuss terms; AI negotiation is not implemented in this transaction branch
>
> 🧾 Once both sides accept the same terms, the platform creates an internal Brokerage AI invoice
>
> 💳 The buyer pays through PayPal Checkout in Sandbox; the application tracks an application-managed hold
>
> 📦 The seller ships, the buyer confirms, a **return window** runs
>
> 💸 When it closes, **PayPal Payouts** releases the agreed funds to the seller, with the transparent 3% platform fee retained by the platform

PayPal Checkout does not collect or verify shipping addresses or delivery. Physical-goods delivery and service fulfillment expectations are recorded in terms accepted by both parties; tracking references are not carrier-verified.

## 🏗️ Architecture

### Transaction Intelligence — AG Studio

Brokerage AI includes a role-specific, read-only analytics workspace at `/analytics`, powered by AG Studio 3.1.0 (AG Grid and AG Charts). Buyers can explore verified captured purchase activity, return-window funds, lifecycle distribution and searchable transaction history. Sellers can explore deal pipeline, listing performance and recorded payout statuses. Dashboards include a Brokerage AI Deal Health Overview widget and are editable with drag, resize and cross-filter controls.

Analytics is built from owner-scoped server-side reads and sends only sanitized rows to AG Studio. Payment totals require captured payment records; seller payout totals use actual payout records. No database changes are required. A trial key is optional for local use; set `NEXT_PUBLIC_AG_STUDIO_LICENSE_KEY` in the environment for a licensed deployment. See [`docs/AG_STUDIO_ANALYTICS.md`](docs/AG_STUDIO_ANALYTICS.md).

## ⚙️ Setup & Installation

<details open>
<summary><b>1. Prerequisites</b></summary>
<br>

- Node.js 18+
- A free [PayPal Developer](https://developer.paypal.com/) account (Sandbox)
- A free [Google AI Studio](https://aistudio.google.com/) API key (Gemini)
- A free [Supabase](https://supabase.com/) project

</details>

<details open>
<summary><b>2. Clone & Install</b></summary>
<br>

```bash
git clone https://github.com/<your-username>/brokerage-ai.git
cd brokerage-ai
npm install
```

</details>

<details open>
<summary><b>3. Environment Variables</b></summary>
<br>

Create a `.env.local` file in the root:

```env
PAYPAL_CLIENT_ID=your_sandbox_client_id
PAYPAL_SECRET=your_sandbox_secret
PAYPAL_ENVIRONMENT=SANDBOX

GOOGLE_GENERATIVE_AI_API_KEY=your_gemini_api_key

SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key
```

</details>

<details open>
<summary><b>4. Database Setup</b></summary>
<br>

Run the schema migration in `/supabase/schema.sql` via the Supabase SQL editor, or:

```bash
npm run db:migrate
```

</details>

<details open>
<summary><b>5. Run the App</b></summary>
<br>

```bash
npm run dev
```

Visit `http://localhost:3000`

</details>

<details open>
<summary><b>6. Test the Full Flow</b></summary>
<br>

1. Sign up as a **Seller**, create a listing
2. Sign up as a **Buyer** (separate browser/incognito window), start a deal on that listing
3. Choose **Self Chat** or **AI Negotiate** and watch the deal progress through to payout

> 💳 Use [PayPal Sandbox test accounts](https://developer.paypal.com/dashboard/accounts) for the buyer and seller payment flows — no real money is ever involved.

</details>
